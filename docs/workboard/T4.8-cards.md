**Blocks** : T4.8.5

### Description

Implémenter `src/agent/fd_resolver.{hpp,cpp}` : un worker pool de 4 threads qui résolvent `/proc/<pid>/fd/<fd>` → full path avec timeout strict 10ms par event. API simple, thread-safe, observable.

### Tasks

- [ ] Créer `class FdResolver` (header) avec enum `Outcome` (OK, TIMEOUT, ENOENT, EPERM) et struct `Result`
- [ ] Implémenter le worker pool : 4 threads fixes, `std::deque<Job>` protégé par mutex + `std::condition_variable`
- [ ] `Result resolve(uint32_t pid, int32_t fd)` : bloque jusqu'à 10ms via `std::future::wait_for(timeout)`, retourne `Result` avec outcome
- [ ] Path validation post-resolution : check `..`, `/proc/`, `/sys/`, `/dev/`, size > 4096 → return EPERM
- [ ] Structured logging JSON sur chaque resolution (event_id, pid, fd, outcome, duration_ms)
- [ ] Histogram latency via MetricsServer (T4.8.6)
- [ ] Tests unitaires `tests/test_fd_resolver.cpp` (cf. spec §5B.4) : 20+ cas (OK, ENOENT, EPERM, timeout, race conditions)
- [ ] Fuzzing harness `tests/fuzz_fd_resolver.cpp` (libFuzzer)
- [ ] Coverage ≥ 85% (gcov)

### Acceptance

- [ ] `make test_fd_resolver` → 0 fail
- [ ] `make fuzz-fd-resolver RUNS=1000000` → 0 crash
- [ ] `make coverage` → ≥ 85% sur `fd_resolver.cpp`
- [ ] `make test-asan` → 0 leak
- [ ] `make test-tsan` → 0 race
- [ ] Benchmark : 1M resolutions synthétiques, P99 < 10ms, throughput > 50k res/s

## T4.8.5 — FimCollector (orchestrateur)

**Owner** : TBD
**Priority** : P0
**Estimate** : 2d
**Depends on** : T4.8.1, T4.8.2, T4.8.3, T4.8.4
**Blocks** : T4.8.6, T4.8.7

### Description

Implémenter `src/agent/fim_collector.{hpp,cpp}` : orchestrateur du pipeline FIM. Possède le ring buffer consumer thread, le rate limiter per-PID (token bucket 100/s), la queue bornée (100k), le worker pool FdResolver, le CircuitBreaker, le MitreMapping, le YaraEngine hook, et publie vers le SENDER.

### Tasks

- [ ] Créer `class FimCollector` (header) avec config struct `FimConfig`
- [ ] Ring buffer consumer thread : poll 10ms, push vers queue
- [ ] Rate limiter per-PID : token bucket, 100 tokens/s/PID, burst 100, refill 1ms granularity
- [ ] Queue bornée `BoundedQueue<Event>` (100k capacity, drop newest sur full)
- [ ] Worker pool : dispatch les jobs vers FdResolver, reçoit les Results
- [ ] MitreMapping::tag() appelé sur full path
- [ ] YaraEngine::scan_file() appelé sur full path résolu (opt-in, throttling 30s par path)
- [ ] Publication vers SENDER : format JSON structuré, event_id propagé
- [ ] Watchdog thread (5s tick) : check ring consumer alive, workers UP, queue depth < 80%
- [ ] Graceful shutdown : SIGTERM → drain queue (30s timeout) → close ring buffer → detach BPF
- [ ] Structured logging JSON partout
- [ ] Métriques Prometheus : `fim_events_total`, `fim_queue_depth`, `fim_queue_drops_total`, `fim_ebpf_probes_loaded`, `fim_workers_active`

### Acceptance

- [ ] `make test_fim_collector` → 0 fail (mocks pour ring buffer, SENDER, YARA)
- [ ] Integration test : ring buffer → queue → resolver → yara → sender mock (1 event)
- [ ] Rate limiter : 1 PID × 10k events → exactement 100 passent, 9900 drops
- [ ] Queue overflow : 200k events synthétiques → drop count = 100k (la moitié droppée)
- [ ] Watchdog : tuer le worker thread → restart auto en < 5s
- [ ] Graceful shutdown : SIGTERM → exit 0 en < 30s, queue vide
- [ ] Coverage ≥ 85%
